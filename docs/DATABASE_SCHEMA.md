# Database schema

Migrations create `accounts`, `jobs`, `activity_events`, `schema_migrations`, `game_datasets`, `game_entities`, `knowledge_entries`, `knowledge_sources`, `knowledge_revisions`, `character_link_reviews`, `character_link_review_history`, `character_field_reviews`, `character_field_review_history`, `canonical_character_snapshots`, `character_reconciliation_snapshots`, and `source_check_events`. `accounts` are independent local profiles. `jobs` persist status, progress, timestamps, errors, and result JSON for background work. `activity_events` stores sanitized local application events. Knowledge and source entities belong to versioned datasets; revisions record draft previews, approvals, and carry-forward counts. Search reads only approved datasets. Superseded versions remain available for historical inspection. Omitted records and their provenance are copied forward during approval. Character identity reviews bind a decision to an evidence fingerprint and source versions; the append-only history records every accepted, rejected, or deferred review. Field decisions bind to a specific character link, field, source versions, and observed values; reviewers may select one currently observed source value or defer, with each change audited. Canonical projection snapshots preserve accepted candidate data; full reconciliation snapshots preserve matched and unmatched records, conflict evidence, coverage, review states, unmatched guide pages, and source versions. Source check events record each successful live fetch separately from import approval, including source/dataset version, check timestamp, content hash, and optional upstream revision. They do not encode a generic freshness threshold. Canonical and reconciliation snapshots and source-check events are historical review artifacts, not approved calculation datasets. SQLite foreign-key enforcement is enabled on every connection.

Follow-on migrations add global versioned datasets and account-owned inventory/planning entities. Account-owned foreign keys should be composite `(account_id, id)` references; physical equipment uniqueness and hypothetical state separation are enforced in the database where possible. Unknown quantities use nullable quantities plus explicit completeness/provenance metadata, never a fabricated zero.

Migrations are immutable after release and applied transactionally. The current database file is `storage/database/genshindex.sqlite`; it is created on first launch and excluded from version control. The knowledge seed is idempotently loaded during server startup.
